# 問い合わせ方式A・Bの再評価

確認日：2026-11-22（JST）。対象は既存の無料Google Groups・Gmail窓口。既存の調査・開発者回答を再利用し、今回の論点に限りPPC公式資料を確認した。個別サービスの適法性を認定した資料ではない。B案の実装は維持し、採否は開発者判断前。

## 処理を分けた適用判断

| 処理 | 今回の評価 | 確定に必要なこと |
| --- | --- | --- |
| 利用者がメールアプリから開発者に送信 | 本人からの取得と、開発者による第三者への提供は別の行為。通常の問い合わせ取得そのものについて、国外メール利用だけで法28条の事前同意を一律必須とは導けない（今回の適用上の推論）。利用目的の明示と第三者提供同意も区別 | 取得目的の説明。要配慮情報等を求めない。本人以外の情報を送る場合は別評価 |
| 開発者が取得後、返信・転送・保存等をGoogleに取り扱わせる | 事業の問い合わせ履歴が個人情報データベース等を構成するか、Googleが個人データを取り扱う契約・実態かを判断する。最初の受信からGoogleを介す設計なので、取得後だけを見て自動配信・保存を除外しない | Groupsの会話保存、Gmail配信コピー、返信の経路別に処理主体・目的・契約を記録 |
| Googleのサービス上の保存・処理 | 外部サービス利用だけで第三者提供とは限らないが、無料メールを「事業者が取り扱わないクラウド」とみなす証拠はない | 契約上の取扱いとアクセス制御を確認。暗号化・広告目的不使用だけで非取扱いとしない |
| 法定の事前同意 | 個人データの外国第三者提供に該当し、同等国・基準適合体制・法定例外等の根拠を利用できない場合は、法28条の情報提供と事前同意が問題となる。国内法上の委託というだけでは外国提供の検討は終わらない | 適用根拠を経路別に確定。法27条側の要件や委託監督も別途確認 |
| 任意の説明 | 目的、メール事業者、国外処理の可能性、保持・削除・権利窓口の説明はA・Bとも有用 | 説明を読んだことと法定同意を混同しない |

根拠：PPC [Q4-17（利用目的の明示）](https://www.ppc.go.jp/all_faq_index/faq1-q4-17/)、[Q7-53（クラウドの取扱いの判断）](https://www.ppc.go.jp/all_faq_index/faq1-q7-53/)、[Q12-4（外国事業者と国内サーバー）](https://www.ppc.go.jp/all_faq_index/faq1-q12-4/)。受領先の外国性はサーバー所在地だけで決めず、日本国内の取扱い等の条件も確認する。

法28条の条件と同意時の国・制度・保護措置の情報提供はPPC [外国第三者提供編2・3・5](https://www.ppc.go.jp/personalinfo/legal/guidelines_offshore/)を参照。国等が特定できない場合には規則17条の代替説明の条件もあるが、調べずに「不明」とすればよい制度ではない。契約法人の所在国と全処理国は異なり、施設一覧から国を推測しない。

## A・B比較

| 観点 | A：従来のメール導線＋説明 | B：チェックボックス＋本文記録（現在の実装） |
| --- | --- | --- |
| 法的必要性 | 別途同意を要しない根拠が確認できる経路に適する。法定同意が必要な提供を説明だけで正当化できない | 同意を根拠とする経路の意思表示を補助。ただしチェックボックスが法定の唯一の方法ではなく、現実装で要件充足済みともいえない |
| 利便性 | すぐにメール作成でき、JavaScriptや定型文の保持を要求しない。従来の不具合報告テンプレートも利用可 | 長い説明・チェック・本文確認の手間が増える。メール作成失敗時は手動手順が必要 |
| 運用負荷 | 説明更新、問い合わせ・権利請求・削除の既存運用を維持 | 受信ごとの意思表示、説明版、範囲、同意能力を確認。不備への照会、説明版保管、記録保存の管理が増える |
| 記録の実効性 | メール送信から法定同意を自動推定しない。必要なら別途意思確認 | サイトはチェック状態を保存・送信せず、受信本文だけが記録。送信者が同意文・版・URLを編集・削除できる。改変防止、チェック日時、説明閲覧の証明なし。記載があっても本人性・能力・説明理解を確実に証明しない |
| 直接送信・旧メール | アプリ、規約、手入力の直送に自然に対応。ただし後続の提供根拠は必要 | UIを経ない直送を防げず、同意文欠落もあり得る。旧メールへの遡及同意にしない。受信時点でGoogleに届くため、受信後の再確認で受信前の根拠不足を修復できない |
| 未成年者 | 法定同意不要の取得まで年齢一律で遮断しない。必要な処理に対して能力を別評価 | チェックだけで年齢・能力・保護者同意は確認できない。現在はその機能なし |
| 権利請求 | 通常の窓口で受け付け、必要最小限の本人確認 | 包括同意なしだけで一律拒否しない。ただし「最小限の返信」も根拠不要とは限らない。必要なら追加提供を避ける受付経路を用意 |

PPC [Q1-62（子どもの同意能力）](https://www.ppc.go.jp/all_faq_index/faq1-q1-62/)は年齢・情報・事業に応じた個別判断を示す。13歳以上のストア設定や規約の法定代理人条項だけでBの同意を有効と判断しない。

## 提案と採用条件

通常の問い合わせ取得に一律の国外移転同意が必須であるとする以前の前提は採用しない。まずGoogleによる処理と移転根拠を確認し、同意を別途要しないと判断できるなら、利用者負担と記録管理の少ないAを推奨する。確認前にAへ戻す決定はしていない。

法28条の同意を根拠とする必要がある場合、Bは補助となるが現状のまま公開可能とは判定しない。受信・自動配信時点の根拠、必要な情報提供、直接送信・同意不備・未成年・権利請求への経路を確定する。別の適切な基盤や契約で根拠を確保する選択肢も含め判断する。A/BはUIの違いで、サービス契約の問題を自動的には解決しない。

今回、contactのHTML、共有include、JS、CSS、文言データは削除・変更していない。公開本文はB採用を既定にせず、送信前説明への案内に統一した。Bを採用する場合は説明版と採用文言、Aなら具体的な従来導線と説明を開発者が確認し、実装差分を別途作成する。

## 記録・権利運用の残事項

- 同意文を編集・削除したメールは、受信した実文で意思表示を個別評価する。欠落を同意済みと補完しない。
- Bを使うなら説明の版を保管し、受信日時・対象・根拠・説明版との対応を必要最小限で管理する。チェックログ新設が一律必須という判断ではない。
- 通常の問い合わせ保存は合意済みの1年・月次削除・最長1年1か月を維持。同意記録や第三者提供記録に別の法定保存義務があるかは経路・記録方式に応じて判断し、矛盾があれば限定例外と説明を確定する。一律に無期限保存へ延長しない。
- 停止・削除等の申出に、同意撤回が含まれるか、以後の提供を止める範囲、法令・紛争上必要な限定保存を個別に判断する。申出を受け付けるための追加情報を必要最小限にする。
