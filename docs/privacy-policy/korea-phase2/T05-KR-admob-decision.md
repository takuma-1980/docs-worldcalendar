# T05-KR AdMobの条件付き判断と不足証拠

判断基準日：2026-11-23（JST）。対象は作業ツリーのGMA25.4.0・NPA構成。根拠事実と出典は[証拠資料](T05-KR-admob-evidence.md)、未送信の照会案は[Q1–Q6](T05-KR-admob-google-questions.md)。Phase 2のKR-01／KR-02の追加判断材料とする。

## 1. 現在の判断

**韓国で同意なしにNPAを利用できるとの判断は、現時点では成立を確認できない。** 全員に必ず同意が必要との結論も未確定。未確定なのは、目的別の処理主体、直接収集か提供か、独自利用、受領者・国・期間、および各処理に使える非同意根拠である。

実装では25.4.0を指定し3箇所の明示ロードに`npa=1`を付けるが、Application起動時に初期化し、既存統合Manifestに広告ID権限がある（証拠S01–08）。したがって、NPAから「無収集」「匿名」「初期化前の同意取得済み」を導けない。実アカウントの契約と配布版の実通信は未確認。

通常AdMobを一律に委託と扱う証拠は不足している。Googleの[サービス分類](https://business.safety.google/adsservices/)と[C-C規約](https://business.safety.google/adscontrollerterms/)は独立した目的決定を検討する材料だが、PIPAの区分を確定するものではない。**通常広告・頻度管理・測定・不正防止・診断／改善・RTBを処理単位で分類し、混在を許容する。** Googleに独自目的処理がある場合でも、限定された別処理の委託可能性まで否定しない。

## 2. 分類前に確認する前提

1. **PIPAの対象性**：韓国向け提供等を前提に評価する。日本所在・個人開発であることだけでは除外しない。[PIPC海外事業者案内の公表本文](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=10056)（K06）。
2. **個人情報性**：項目名だけでなく、各受領者が利用できる他情報との結合可能性を評価する。氏名不明、AAID削除、切り詰めたIP、GoogleのPII定義だけでは匿名と認定しない。法2条の定義は[Phase 2の分類表](T05-KR-research.md)を参照し、本件の結合能力・保持はQ2–5で埋める。
3. **役割と経路**：端末→Googleの物理通信、開発者によるSDK導入・開始・データ取得設定、Googleの目的決定を併せて評価する。開発者が生IDを保存しないことは重要な事実だが、提供者／委託者でない証明にはならない。
4. **根拠の分離**：収集利用15条、第三者提供17条、委託26条、国外移転28条の8をそれぞれ判定する。一つの根拠が他を自動充足しない。

## 3. 三つの法的構成

以下は実処理が確認された後の当てはめ条件であり、Googleの回答を予測したものではない。

| 構成 | 成立を検討する条件 | 支える証拠／反対方向の事情 | 残る義務・非同意ルートの条件 | 不足証拠と解決方法 |
| --- | --- | --- | --- | --- |
| A Googleの本人からの直接収集 | 当該段階ではGoogle自身が収集主体で、開発者からの提供・委託ではないと、契約・目的決定・実装・本人への説明を通じて評価できる | SDKがGoogleへ通信し、開発者の生ID保存処理は未検出。一方、開発者が組み込み・初期化・要求を制御する。サーバーを経由しない事実だけでは不十分 | 当該直接収集段階に開発者の国外移転同意を要しない可能性。Googleの15条等の処理根拠、国外処理国の説明、後続の第三者移転は残る。開発者自身の処理・説明・SDK管理の義務を別に判定 | Q1–3で本人に対する主体・独自目的・開始条件を取得。Q4–6でGoogle自身の根拠と後続共有を確認し、K05をSDK事例に適用できるか韓国法の専門家又はPIPCへ具体的データフローを示して確認 |
| B 開発者からGoogleへの第三者提供 | 開発者の処理としてSDKで情報を利用可能にし、Googleが自らの目的で利用する等、17条の提供に該当する | G03・G07は独立目的／独自利用を検討する材料。自動的な法的分類ではない。NPAでも残存処理あり | 15条と17条の根拠に加え、国外なら28条の8の根拠・開示・保護措置が必要。1項3号の「必要委託・保管」公表ルートは使えない | Q1–5で提供項目・目的・主体・国・期間を確定。Q6の主張を一次根拠に照合。根拠がなければ必要な同意又は処理停止・構成変更を検討 |
| C 開発者の処理業務の委託 | 対象処理が開発者の業務として指示・監督下で実施され、契約に目的外処理禁止等があり、Googleの独自目的処理と区別できる | G04は限定Processor Servicesの指示下処理を定める。ただし通常NPA全体への適用証拠なし。NPAはG02のProcessor機能として列挙されていない | 15条の根拠、26条の文書・公開・監督・再委託条件。国外なら28条の8。3号を使うには本人との契約締結・履行に必要な委託／保管であることと法定事項公表又は通知が必要 | Q1–2で対象処理・契約・監督・目的制限を確定。Q4–5で受託／再委託先等を取得。開発者側で広告処理の必要性・代替可能性を評価。単なる広告収益上の必要性で通さない |

Aについての公式根拠は[PIPC直接収集解説](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS292&mCode=C050010000&nttId=10972)（K05）。これは海外事業者の直接収集と、その後の別主体への移転を区別する解説である。SDKへの個別認定ではなく、同じ外国の別法人への移転も問題になる。Aが成立してもGoogle→別法人／RTBの評価を省略しない。

## 4. 同意なしを検討するための法的ゲート

| ゲート | 成立に必要な判断記録 | 現状 |
| --- | --- | --- |
| 15条：契約必要性 | 広告ごとの目的・必要データ・利用者との契約の関係。SDKを動かすことが暦機能提供に必要か、代替・縮小可能性 | 未評価。無料・広告付きと規約に書くだけでは成立証明にならない |
| 15条：正当利益 | 具体的利益、必要性、項目・期間の最小化、予測可能性、権利への影響と明白な優越、拒否手段等 | Q2–5待ち。Googleの一般的なlegitimate interestsの説明を開発者の比較衡量に代用しない |
| 17条：第三者提供の非同意根拠 | 1項2号の列挙根拠と収集目的内性、又は4項の合理的関連性・不利益・安全措置等の充足 | 未確認。15条1項4号は17条1項2号の列挙に含まれない。17条4項を新規の広告共有全体の包括根拠としない |
| 26条：実際の委託 | 契約上の目的制限、業務・受託者公開、監督、再委託への委託者同意、必要時販促委託通知の該当判断 | 通常NPAの包括委託を認定する資料なし |
| 28条の8：非同意の移転根拠 | 1項2号の特別規定、3号の必要委託／保管＋公表／通知、4号の所定認証と措置、5号のPIPC同等性認定のいずれかが当該処理に適用 | 実適用できる根拠は未確認。SCC・Googleの一般認証・日本の基準適合体制を代用しない |
| 透明性・保護・権利 | 正確な項目・国・目的・期間・拒否／権利手続、契約等への保護措置反映。14歳未満は必要な同意の代理人対応を別判定 | 法人名以外に大きな空欄あり。Googleの一般設定・AAID削除だけで全処理停止としない |

15・17条の根拠は[現行条文](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1006183947)（K01）、26条は[1–3項](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025127467)・[監督](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029331841)・[再委託](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?ancYnChk=&chrClsCd=010202&lsJoLnkSeq=1029335559)（K02）。本表の「成立証明にならない」「包括根拠としない」は本件証拠の不足についての判断であり、一律の禁止を引用したものではない。

国外移転に同意を使う場合、[28条の8第2項](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334869)の項目、国・時期・方法、受領者名・連絡先、目的・保有利用期間、拒否方法・手続・効果を先に確定する。公表・保護措置は[施行令31条](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1033215161)と[29条の10](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=182203)を照合する。別個同意を置くだけで情報不足・保護措置不足は解消しない。

## 5. 回答を判断に変える受入条件

| 質問 | 回答で埋めるべき証拠 | 回答後の処理 | 未解消となる回答の例 |
| --- | --- | --- | --- |
| Q1 | 実契約・対象機能・適用条項・版・有効条件。所有者の受諾記録と対応 | 各処理にC-C／DPT／別規約を割当て、処理事実と矛盾がないか確認 | サービス分類URLだけ、「NPAはプライバシー対応済み」 |
| Q2 | データ×目的ごとの法人、指示・目的決定、独自利用／結合の有無と制限 | A/B/Cを処理ごとに仮分類し、PIPA上の当てはめを確認 | controller／processorの呼称だけ、「個人識別情報は受け取らない」 |
| Q3 | 25.4.0・NPAの初期化前後の送信、AAIDなし等の分岐、設定効果 | 実装と照合し、必要時の測定条件と同意開始前ゲートを確定 | 25.5.0の一般開示だけ、初期化は対象外の広告ロード説明 |
| Q4 | 法人・窓口・国・保持起算点／上限又は具体的基準・例外・権利手続 | 台帳と韓国向け説明を埋める。法定期間説明に足りるか審査 | 「世界中」「必要な期間」、契約法人の国だけ、レポート期間だけ |
| Q5 | 入札の有効状態・相手一覧・未落札者／配信先・データ・役割・国・期間・制御 | Google受領と後続共有を別経路で判定。受領者が増えれば各根拠・説明を再確認 | 「メディエーションSDKなし」「デフォルトのみ」 |
| Q6 | 韓国向け公式要求と根拠、Google／開発者の分担、APIが扱う同意範囲 | 主張の根拠を法令と照合し、法務判断・UI仕様へ反映 | EU同意ポリシーだけ、UMP導入だけ、韓国向け根拠のない「同意不要」 |

Googleの無回答は「なし」や「同意不要」という回答に変換しない。契約・処理表と矛盾する返答は対象版・処理を指定して再照会する。法的な当てはめが残る場合は、Googleの回答とソース証拠を添付して韓国PIPAを扱う専門家へ依頼し、直接収集のSDK事例に疑義があればPIPCへの具体的照会を検討する。問い合わせは開発者が別途送信する。

## 6. 開発者側で回収する資料

Googleへの質問を増やさず、次の事実は開発者側でそろえる。今回は管理画面・Android設定を変更しない。

| 資料 | 必要な範囲・完了条件 |
| --- | --- |
| 契約記録 | 認証済みConsoleのTermsを保存し、法人・版・参照組込み・受諾履歴をQ1と照合。新規受諾は別行為 |
| Console設定記録 | 日時・対象アプリ／広告ユニット・対象国と、メディエーション、入札／ウォーターフォール、広告ソース、RTB関連制御、限定Processor機能の有効状態を記録。画面にない事項は未確認を維持 |
| 配布対応 | 現在の候補ソースと最終成果物のSDK・Manifest・NPA経路を対応付ける。Phase 1の再提出を一律に要求するものではない |
| 必要な実測 | Google説明で残る開始時点・信号を、新規起動／初期化のみ／NPAロード／AAIDあり・削除済み等で検証。第三者SDK・バックエンド保持を端末測定だけで証明しない |
| 非同意根拠の評価 | 利益・必要性・代替・最小化・権利影響を処理ごとに文書化。広告収益だけで結論を出さない |
| 年齢・権利運用 | 14歳未満の扱い、説明の理解可能性、拒否・停止・請求を誰がどう受けるかを確定。Google側データを開発者が削除できると保証しない |

## 7. 回答後の最終判定手順

1. **対象を固定する**：SDK・アプリ版、NPA、地域、年齢、広告ソース、契約版を記録。別設定への回答を流用しない。
2. **処理台帳を埋める**：初期化、広告要求、測定等ごとに項目・目的・主体・国・期間・後続共有を確定。空欄があれば、その処理は判定保留。
3. **A/B/Cと根拠を決める**：Googleの呼称ではなく実態・契約を基に分類し、上記法的ゲートを処理単位で確認する。
4. **同意なしの可否を判定する**：残存するすべての対象処理に適法な非同意根拠があり、開示・権利・保護措置・年齢要件を満たす場合に限り、「この版・設定・対象範囲で同意なしNPAが可能」と判断する。Aのみ成立しても、他処理の根拠が欠ければ全体を許可しない。
5. **条件が成立しない場合**：該当処理に必要な事前同意を取得する、又は当該処理を停止・制限できる構成へ変更する。同意ルートは初期化・自動処理の開始前制御と拒否・撤回を含めて[T07](T07-consent-notice.md)へ引き継ぐ。NPAフラグ又は広告枠非表示だけで停止済みとはしない。
6. **根拠が未確定の場合**：「同意なし利用は未確定」を維持する。未確定な受領者・国・期間を仮値で埋めて同意ルートを完成扱いにもしない。必要な追加証拠、取得担当、取得方法を残し、広告開始の承認を保留する。

最終判断記録には、`判定日／対象版・設定／処理ID／A・B・C／15条根拠／17条根拠又は非該当理由／26条措置又は非該当理由／28条の8根拠又は非該当理由／根拠資料／説明・拒否手段／判断者／再確認条件`を保存する。契約・SDK・目的・広告ソース・法令が変わった場合は該当部分を再評価する。
