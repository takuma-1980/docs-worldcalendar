# T07 同意・告知・拒否・撤回の要件

調査日：2026-11-22（JST）。状態：一部調査済み。以下は条件付き実装要件であり、今回のコード変更や同意ルート採用の決定ではない。

## 1. 同意の要否と根拠

| 処理 | 同意不要と判断できる条件／根拠 | 同意が必要となる条件 | 告知・権利・実装条件 |
|---|---|---|---|
| AdMob NPA | 個人情報に当たらないこと又は15条等の非同意根拠が具体的に成立し、提供・移転にもそれぞれ根拠がある | 個人情報の収集利用・提供に非同意根拠がなく、同意に依拠する場合。国外移転があり他の移転根拠がなければ別個同意 | 項目・目的・受領者・国・期間・拒否等を確定。現在は成立未確認。必要ならSDK初期化前に取得 |
| Analytics停止後 | 全体停止を維持し、新規収集を実際に行わない対象版 | 将来収集再開・目的追加をする場合は再評価 | 新規収集のための同意UIは不要。過去データは別に権利対応・破棄・移転を検討 |
| 端末内の予定・通知・ウィジェット | 開発者が当該処理の個人情報処理者に当たらない範囲、又は要求された機能に必要な15条1項4号等が成立 | 23条の敏感情報等、別の同意条件が発生する処理を開発者が行う場合 | 予定内容を広告・診断へ付加しない。通知・ロック画面・共有端末での表示と削除を案内 |
| 外部カレンダー | 利用者が選択する連携に必要な処理で非同意根拠が成立、又は別サービスの直接収集と分類される範囲 | 開発者の第三者提供・移転となり、その非同意根拠がない場合 | 権限許可前の機能説明、保存先選択、同期の影響、解除と外部削除。Android権限だけで法定同意としない |
| ICS | 本人の購読要求に必要なGETが15条1項4号等で説明でき、接続先の直接収集等と整理できる範囲 | 開発者提供・移転として同意を要する情報が加わる場合 | 通信先・URLに含む秘密情報・IPの説明、解除で更新停止。全相手の保持期間を同一としない |
| OSバックアップ | 利用者とOS提供者の独立処理と整理できる範囲、又は必要委託・保管として移転公表ルートまで成立 | 開発者責任の移転で他根拠がなく、同意ルートが必要な場合 | 対象に予定DBが含まれること、OS設定・復元・削除方法を説明。SDKの同意状態を無条件復元しない |
| 問い合わせB | 回答に必要な15条1項4号、法的権利対応等の根拠が成立。Google委託・保管が28条の8第1項3号の必要性＋法定公表等を満たす場合 | それらの根拠が成立せず同意に依拠する範囲、独自目的第三者提供等 | 方式Bは維持。収集利用・第三者提供・移転の範囲を明確化。画面を通らない受信の根拠を確定 |

一次根拠：[15・17・21・22条](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1006183947)、[28条の8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334869)、[直接収集の区別](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS292&mCode=C050010000&nttId=10972)。非同意根拠の立証責任・区分した公表は22条3項も確認する。

## 2. 同意に依拠する場合の必須表示

| 同意対象 | 説明内容 | UI上の分離 |
|---|---|---|
| 収集・利用 | 目的、情報項目、保有・利用期間、拒否権・不利益 | 規約受諾と別。任意の広告処理を基本機能の必須同意へまとめない |
| 第三者提供 | 受領者、目的、項目、受領者の保有・利用期間、拒否権・影響 | 収集利用と区分し、独立した選択が必要な範囲を維持 |
| 国外移転 | 対象項目、国・時期・方法、受領者名と連絡先、目的・保有利用期間、拒否方法・手続・効果 | 28条の8の別個同意。単なる「ポリシーに同意する」や「Googleを利用」に置換しない |
| 14歳未満 | 上記に加え代理人の同意確認、子ども向け平易な説明 | 子ども本人のチェック・年齢自己申告を代理人確認に代用しない |

同意対象が変わる場合は変更の通知と必要な再同意を取得する。既知でない実処理国・期間を「全世界」「必要な間」とだけ記して法定説明を満たしたことにしない。不明値が残る場合はGoogleへの確認又は対象処理停止案を先に確定する。

## 3. Androidの条件付き改修仕様

| 対象クラス・機能 | 現状 | 同意ルートを採用する場合の要求 |
|---|---|---|
| `WorldCalendarApplication.onCreate()` | 47行で無条件`MobileAds.initialize(this)` | アプリ起動と広告開始を分離。地域・年齢・同意が処理を許すまで初期化しない。バックグラウンド・ウィジェット起動でも迂回させない |
| `AdMobBanner.kt` | 初回・再ロードの2経路 | 共通ゲートを通し、拒否／撤回後の再Compose・サイズ変更・自動更新で再ロードしない |
| `AdMobNativeAd.kt` | 1経路でロード | ゲート、保留中要求の競合防止、取得済み広告の破棄・表示停止 |
| `AdRequestFactory.kt` | NPA要求の共通化 | NPA維持。Googleへ伝える制限と法的同意状態を混同しない。第三者アダプタの同等制御は個別確認 |
| 初回案内・設定画面 | 規約・ポリシーリンク、広告の任意拒否・撤回なし | 拒否・後で選択する導線、いつでも変更できる入口。権利窓口、拒否影響・Google側削除の限界も案内 |
| `TermsConsentRepository` | 規約版・日時等をバックアップ対象DataStoreに保存 | 広告同意とは別レコード。規約同意済みを広告許可へ移行しない。広告同意レコードは端末移行で無条件に有効化しない |
| Backup規則・復元 | ユーザーDBと一部設定を移行 | 新しい広告同意保存先はバックアップから除外する案を推奨。復元先では再判定。現設定に広告同意を混在させない |

開始順序案：ローカル機能起動 → 端末内の地域・年齢区分・同意版の確認 → 必要な説明／代理人確認 → 許可状態確定 → 対象SDK設定 → Mobile Ads初期化 → バナー／ネイティブ要求。Google資料も同意又はRequestConfigurationが必要な場合に初期化前対応を求める。[Google初期化ガイド](https://developers.google.com/admob/android/quick-start)

Manifest内の`MobileAdsInitProvider`等による自動起動も点検し、Applicationの呼出しを遅らせるだけで全通信停止とは断定しない。初期化前の観測を含め、対象25.4.0で不要送信がないことを確認する。実現できないなら対象地域でSDKを動かさない構成等を別の改修として検討する。

同意状態案：未選択／許可／拒否／撤回／期限又は説明版変更により再確認。保存候補は対象目的、通知版、選択結果、取得時刻、適用地域、年齢区分、確認方法の最小限。本人の氏名・生年月日・AAIDを新たに集めて照合台帳にすることを既定にしない。端末内証跡は改変・削除可能であり完全な立証を保証しない。保護者確認の必要な証跡を端末内だけで保持できるかは別途評価する。

**保存期間：一律の法定年数を今回確定できていない。** 処理継続中の根拠提示、撤回後の証明・紛争・法定保存の必要性と21条の破棄義務を照合して期限を決める。APPI第三者提供記録の期間を韓国の全同意記録へ転用しない。問い合わせBではチェック状態・選択時刻を保存せず、受信メールの意思表示・説明版・受信情報と説明版履歴を用いる方針を維持する。

## 4. 拒否・撤回・移行・地域

| 場面 | 要求する動作 |
|---|---|
| 未選択・通信エラー・根拠不明 | 同意が必要な広告処理を開始しない。カレンダーの基本機能は利用可能にするという設計案 |
| 拒否 | 初期化・広告要求を実行しない。NPA又は制限付き広告なら拒否後も自動配信可能とはしない |
| 撤回 | 保存状態を先に更新し、新規要求・自動更新を停止、画面広告を破棄。起動済みSDKの通信停止能力を検証。停止保証がない場合の次回起動抑止・構成変更等を決める |
| 過去データ | 撤回＝Google保存分の削除ではない。停止範囲、削除請求、本人照合可否、確認済み外部手順を案内 |
| 広告を表示しない | ローカル予定・通知・ウィジェットは継続。空欄・代替表示でもSDKのロードを裏で行わない |
| 既存利用者 | 新版起動時に旧規約受諾から広告許可を推定しない。必要な対象処理の前に初回と同じ判断を行う。旧版への将来の同意は遡及しない |
| 14歳未満 | 同意必要なら確認済み代理人同意まで対象処理を停止。非同意根拠のあるローカル機能とは分離 |
| 日本利用者 | 日本向けAdMob専用同意画面を追加しない方針を維持。日本法上必要と確定した場合は未解決として報告する |
| 地域不明・移動・VPN | 言語／タイムゾーン／SIM／ストア国の単独値は法適用の確定証拠でない。IPの追加収集も目的・根拠を評価。必要最小限の本人申告と保守的な未確定状態などを比較 |

地域別制御は韓国市場公開と実利用者の所在地等を踏まえて設計する。UMPが`canRequestAds=true`を返しても韓国PIPAの全同意を得た状態とは扱わない。

## 5. 実装方式の比較（同意が必要と判明した場合のみ）

| 方式 | 実現できること | 韓国要件への限界・採否条件 |
|---|---|---|
| 独自画面＋共通SDKゲート | 韓国語、目的別・移転別の意思表示、拒否・撤回、説明版管理 | 法定事項・証跡・子ども確認・Googleへの信号を自分で実装する必要。韓国専用要件を満たす候補 |
| Google UMP | 対応するGoogleメッセージ、同意情報更新・プライバシーオプション | 公式資料だけでは韓国28条の8の全項目、別個同意、14歳未満の代理人確認、証跡を満たすと確認できない。導入単独での採用不可 |
| AdMob設定・要求制御 | NPA・年齢等の制限をSDKに伝える | 通知・意思表示取得・移転根拠・撤回UI・証明を代替しない |
| 韓国で広告SDKを起動しない | 広告経路を停止できれば当該処理の同意を不要にできる余地 | SDK初期化・自動Providerも含む実証が必要。他の問い合わせ・ICS・OS等の根拠は残る |

公式：[UMP](https://developers.google.com/admob/android/privacy)、[ターゲティング制御](https://developers.google.com/admob/android/targeting)。法律上の同意とGoogleの配信条件は別々に満たす。

## 6. Android担当への検証項目

- 新規／更新／再インストール／OS復元／既存規約受諾で、説明前のSDK初期化・要求・観測可能な通信を確認する。
- 韓国／日本／地域不明、14歳未満／以上／不明、全同意組合せ、説明版変更、通信失敗を試験する。
- 拒否・撤回後の画面回転、サイズ変更、バックグラウンド復帰、ウィジェット起動でバナー・ネイティブが再ロードされないことを確認する。
- AAID有効／削除済み、実広告ソースごとにNPA要求と残る識別子・初期化処理を照合する。実ユーザーへの広告クリック試験は行わずテスト広告を用いる。
- 同意保存の失敗・破損・競合は許可に倒さない。規約受諾・OS権限を広告許可に代用しない。
- 問い合わせBは同意文削除・版不明・直接メール・代理人メール・権利請求の運用を検証する。今回は送信試験をしない。

法的分類が確定した後だけ、処理・対象年齢・任意性が変わる範囲のPlay申告差分を評価する。Phase 1全体のやり直しを前提にしない。
