# T06 未成年者・子ども向け対応

調査日：2026-11-22（JST）。状態：対象年齢方針確定・運用等は未完了。更新日：2026-11-23（JST）。韓国語原文を優先。[共通証拠](evidence-and-sources.md)、[実装要件](T07-consent-notice.md)を参照。

## 1. 対象年齢の判断

ソースの主機能は暦の表示、予定管理、通知・ウィジェット、外部連携であり、子ども専用の教育・ゲーム等を目的とする証拠は今回の確認範囲では見つからない。これは一般向けと評価する材料だが、ストア宣伝・画像・実際の利用者を含む子ども向け該当性の最終認定ではない。

2026-11-23、開発者が**韓国公開の対象年齢を満16歳以上**と決定した。16歳未満は対象に含めない。以前の「13～15歳又は16～17歳」という未確定記録に優先する事業方針であり、Console設定済み・年齢確認済みという意味ではない。

Google Play「対象年齢とコンテンツ」は**「16～17歳」「18歳以上」**を選択する予定。「13～15歳」以下は選択しない。公開前に現設定と照合して必要な差分のみ保存・提出し、設定日・選択値を記録する。対象年齢申告はコンテンツレーティング、実年齢の認証、法定代理人同意と別であり、16～17歳を成人扱いしない。アプリ単位の申告と他の配信国の対象・ストア説明との整合も確認する。今回はConsoleを操作せず、Phase 1申告全体の再提出も求めない。

今回は保護者同意機能・年齢確認画面を実装せず、Androidコードも変更しない。16歳以上方針だけで、実際に14歳未満の個人情報を処理する場合の義務は消滅しない。年齢不明・対象外利用の判明時に必要な処理制限、削除・権利請求と代理人対応は引き続き公開前に確定する。

## 2. PIPA 22条の2の条件

現行法は法律21445号（2026-03-10改正、2026-09-11施行）。22条の2は2023-03-14新設（2023年改正の施行体系を参照）。現在の原文は、14歳未満の個人情報を処理するため**PIPAによる同意を受ける必要があるとき**、法定代理人から同意を受け、その同意を確認することを要求する。14歳未満がアプリを起動したら全処理に必ず保護者同意という条文ではない。[22条の2原文](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033215047)

| 場面 | 判定・要件 |
|---|---|
| 同意を法的根拠にする広告・提供・移転 | 子ども本人のチェックだけでは不足。法定代理人の同意と確認が必要 |
| 同意を要しない根拠が実際に成立する処理 | 22条の2第1項の同意確認が自動発生するわけではない。必要最小限、目的、子どもの権利と分かりやすい告知は残る |
| 代理人同意を得るための連絡 | 第2項と令17条の2第2項により、代理人の氏名・連絡先等の所定最小限を子どもから取得できる。生年月日・身分証の一律収集を正当化しない |
| 子どもへの通知 | 第3項により容易な形式・明確で分かりやすい言語。大人向け長文リンクだけにしない |
| 未成年者の利用契約 | PIPAの14歳基準と民法上の契約同意能力は別。利用規約の保護者条項をSDK処理の同意としない |

同意確認方法は施行令17条の2が定める。サイトでの意思表示＋SMS通知、本人確認、署名書面、同意事項を送った電子メールへの意思表示返信、電話等の所定方式がある。メールを使う方式を採用する余地はあるが、子どもが「親に了承された」と自己申告するだけでは同じでない。[現行施行令17条の2](https://www.law.go.kr/LSW/lsInfoR.do?efYd=20261110&lsiSeq=291731)。現行36804号の原文で確認した。メール方式は同条第1項5号、代理人氏名・連絡先は第2項。

## 3. Google要件との区別

| 制度 | 目的・条件 | 本件での取り扱い |
|---|---|---|
| 韓国PIPAの14歳未満 | 法律上同意が必要な個人情報処理で代理人同意・確認 | 国別法的基準。13歳未満除外では不足し得る |
| Play対象年齢 | 想定する利用者層の正確な申告 | 法的年齢認証でも同意記録でもない |
| Google Families | 子どもを対象に含むアプリ等への広告・SDK・データ要件 | 内容・対象設定・地域定義で確認。一般向けという自己表示だけで除外しない |
| AdMob子ども向け設定 | SDKへ広告処理の制限を伝える | `setTagForChildDirectedTreatment`等は保護者確認の代用でない |
| AdMob同意年齢未満設定 | Googleの所定地域・規制向け処理 | TFUAを韓国14歳未満の法律適合スイッチとして扱わない |

公式：[Play Families](https://support.google.com/googleplay/android-developer/answer/9893335?hl=en)、[AdMob targeting](https://developers.google.com/admob/android/targeting)。現行Web資料には新しい年齢処理APIもあり、実装対象25.4.0で利用可能か確認してから選ぶ。SDK更新自体は今回の範囲外。

現ソースでは子ども向け／同意年齢未満設定と年齢判定UIは調査範囲で見つからない。NPAであることだけでは児童向けSDK要件の全充足にならない。子ども又は年齢不明利用者へのAAID送信等の制約を、実際のFamilies該当性・SDK構成と照合する必要がある。

## 4. 採用方針と残る条件

採用するのは一般向け暦アプリとして韓国で満16歳以上を対象とする方針。14歳未満も対象に含める案は採用しない。年齢確認UIや保護者同意機能を今回追加しないことを、全利用者が16歳以上だと確認できた根拠にしない。

- 16～17歳を含む未成年者の契約について、法定代理人同意が必要となる条件と取消し等の権利を確認する。規約の同意をSDKの個人情報処理同意へ流用しない。
- 対象外の利用や14歳未満と判明した情報処理では、処理ごとの法的根拠を評価する。同意が必要なら所定の代理人同意・確認まで対象処理を進めない。処理を止める方法・削除と権利対応は未確定であり、実装済みとしない。
- 年齢不明利用者、Google Familiesの地域別定義・実際の対象と宣伝内容、広告設定を公開前に照合する。法律が一律に年齢確認画面を要求すると断定しない。

### AdMob整合性の確認（2026-11-23）

既存証拠はNPA要求、GMA 25.4.0、起動時初期化、子ども向け／同意年齢未満タグと年齢UIが調査範囲で未検出、AdMob画像はデフォルトグループとメッセージ画面のみ。現管理画面の子ども向け設定値を確定する証拠はなく、今回もConsoleは未操作。

| 項目 | 判断・必要な操作 |
|---|---|
| 子ども向け扱い（TFCD等） | 16歳以上方針だけを理由に子ども向け扱いをオンにする必要はない。逆に一律オフを実年齢確認として扱わない。Play連携情報・実際のFamilies該当性とSDK要求を照合し、誤った子ども向け分類があれば根拠を確認して是正する。現値不明のため即時変更は指示しない |
| 同意年齢未満（TFUA） | EEAのGDPR向け設定であり、韓国PIPAの14歳基準や16歳以上方針への適合スイッチにしない。他地域を含むアプリ全体へ一律falseを設定しない |
| 年少者・広告内容 | 16～17歳を含むため、未成年者向け保護・最大広告コンテンツレーティングと全広告ソースを点検する。対象年齢と広告レーティングは別。NPAのみで十分とはしない |
| SDK版と変更要否 | 現行公式資料には新しい年齢処理APIとTFCD／TFUA非推奨の記載がある。25.4.0での利用可否と地域・年齢別要件を確認し、必要なら別のAndroid改修タスクへ。今回はタグ追加・SDK更新・広告設定変更をしない |

公式確認：[Play対象年齢](https://support.google.com/googleplay/android-developer/answer/9867159?hl=en)、[AdMob Families](https://support.google.com/admob/answer/6223431?hl=en)、[SDK targeting](https://developers.google.com/admob/android/targeting)。**現段階で確定した設定変更はPlayの予定年齢区分のみ。AdMobは年齢方針に伴う一律変更を必要と判断する証拠なし。ただし現値・実挙動の照合は未完了**。広告の法的根拠・国外移転等のKR-01・02はこの決定で解消しない。

## 5. 問い合わせ方式Bでの子ども対応

方式Bの事前説明→チェック→本文へ同意文・版を挿入→本人が送信、チェック状態・時刻を保存しない構成を維持する。追加要件は次のとおり。

1. 韓国向けは満16歳以上が対象であると韓国語で明示する。16～17歳も未成年者であり、必要な契約同意を案内する。16歳未満には利用対象外であること、14歳未満には一人で情報を追加送信せず保護者に相談することを短く説明する。年齢・生年月日の入力欄は追加しない。
2. 同意を要する子どもの情報処理なら、代理人へ同意事項を送り、所定の確認が完了するまでその対象処理を進めない。方式Bの子ども本人のメールを代理人返信とみなさない。
3. 代理人の関与・権限を必要最小限で確認し、同意事項・版・確認方式・結果の証跡を限定保持する。チェック日時のサイト保存を新設することは要件にしない。
4. 直接メール・同意文欠落・年齢不明の場合は自動認定せず、不要な追加取得・転送を止めて根拠を評価する。受信後の同意で受信前の処理を遡及正当化しない。
5. 権利請求を保護者同意画面を通らないという理由だけで拒否しない。無同意で可能な最小限の対応根拠と代理人請求手順を確定する。

確定：韓国は満16歳以上、Playは16～17歳・18歳以上を選択予定（未操作）。残課題：子どもから届くメールの実態、代理人確認をどの所定方式で運用できるか、記録の必要期間。確認先と完了条件は [KR-04](release-matrix.md) にまとめた。
